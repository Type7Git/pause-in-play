- All user data (petals, badges, quests, VIT items) flows through the `useRewards()` store: localStorage when signed out, Lovable Cloud tables when signed in, with a one-time local→account migration on first sign-in; why: screens stay storage-agnostic.
- Petal totals are derived from summing `petal_events`, never stored as a counter; why: append-only history avoids lost updates across devices.
- Garden play (src/components/mm/GardenPlay.tsx) never awards petals or badges; flower picks and last-watered time are the only saved garden state, kept in useRewards (auth user_metadata.garden when signed in, localStorage when signed out) and weather is session-only; why: tending is kindness, not a points engine, and weather is mood-like so it is never stored.
- Garden "top X%" and badge rarity come from the public gardenStanding server function, which returns aggregates only, waits for 25+ gardens and never ranks a garden outside the top half; why: comparison should encourage, never shame.
- Enera (formerly Sprout) is reached from the Ask Enera bar on /home, the flower button in every tool page's top bar, and the Enera tile; chat is /enera and voice filing /tell-enera (/sprout and /tell-sprout redirect); code names (askSprout, SproutChat, sprout-guard, tool keys "sprout"/"tell-sprout") stay unchanged because tool keys are stored in library_entries; why: renaming stored keys would break approved library links.
- Account deletion runs in a server function that removes every user-owned row before deleting the auth user; why: app tables hold plain user_id UUIDs without auth FKs.
- Sprout chat runs through a public `askSprout` server function that applies crisis and clinical screens before any AI call and answers only from approved `library_entries`; why: safety rules must hold regardless of the model.
- Sprout admin (/admin) uses the browser client and relies on RLS via `has_role(..., 'admin')` in `user_roles`; why: access is enforced by the database, not by hiding links.
- Sprout chat uses custom bubbles rather than AI Elements because replies are guarded, non-streamed JSON results; why: fixed safety messages and source lines need their own layout.
- Enera's chat reads top-down: introduction, transcript, then the composer, and each new message scrolls to the top of the screen with spare room below; library topics and popular prompts sit in native disclosure lists after the composer; why: answers read like a natural conversation without scrolling back up.
- Offline support uses vite-plugin-pwa (generateSW, NetworkFirst for home + six tool pages) registered only from src/lib/pwa.ts, which refuses dev, preview and iframes; why: a stale service worker in preview would serve old code.
- "Tell Sprout" voice filing runs through public server functions (fileVoiceNote, transcribeVoice) that apply the Sprout crisis screen first, only sort text into fields, and never store audio; why: voice is error-prone and private, so nothing saves without the user confirming.
- Closed-app push nudges are sent by a 5-minute pg_cron job calling /api/public/hooks/send-nudges, authorised by a token stored only in the service-role-only `cron_tokens` table; why: public routes need a caller secret the browser can never read.
- Mood Mapper, Cycle Tracker and the Medicine cabinet keep records on the device only (src/lib/tracking.ts: lum:moods, lum:cycle; src/lib/cabinet.ts: lum:cabinet), with download and delete in Settings; there is no sample data; why: real tracking without storing health data in the cloud before Australian hosting and consent are in place.
- Admin access is granted by a trigger that adds the admin role when an email in the service-role-only `admin_invites` table confirms; Learn content lives in `learn_content` (draft/approved, admin-only writes via RLS) and the admin Users list comes from a server function that checks has_role before any privileged read; why: roles stay database-enforced and never depend on the browser.
- Every tool is defined once in src/content/sections.ts (ACTIVITIES); Lumenera's spaces pick tools from it in src/lumenera/tools.ts (HUB_TOOLS), which also sets each tool page's top-bar title and Back fallback; why: a tool can live in several spaces without duplicating it.
- Colouring scenes live in `colouring_scenes` (layered SVG paths); painting uses per-layer offscreen canvases with source-atop so paint never crosses a layer edge; finished PNGs go to the private `gallery` bucket under the user-id folder; why: lines stay clean and pictures stay private.
- Would you rather? reads live `wyr_questions` and `wyr_characters` (portrait SVGs stored per character); scoring lives in src/lib/wyr.ts; found characters go to `wyr_results` when signed in, localStorage when signed out; why: content is admin-published and results stay private.
- Intimacy & relationships lives under /intimacy (layout renders the privacy banner and an optional device-only WebAuthn lock from src/lib/intimacy-lock.ts); its copy is in src/content/intimacy.ts and library articles are learn_content rows with section=intimacy; check-ins are never saved while personal health saving is disabled; why: this is the most sensitive area of the app.
- Lume Lounge (formerly PeriPals; code names pal/peripal unchanged) access is enforced in the database: SECURITY DEFINER helpers pal_can_see/pal_can_message gate every read, invites are accepted only through the pal_accept_invite RPC, and rules are covered by supabase/tests/peripals.sql; why: this is the only feature exposing one user's data to another.
- Resilient body (/move, /pelvic, /food, /body/why) reads admin-approved content from movement_sessions, session_moves, food_tips and learn_content section=body; personal progress (sessions done, pelvic sets, add-ins) lives on the device only via src/lib/body.ts and "how do you feel" is never stored; why: personal health saving is disabled until Australian hosting is verified.
- Native features in the Capacitor app are reached through window.Capacitor (src/lib/native.ts: nativePromise/addListener) rather than bundling @capacitor/* packages; why: the app loads this site remotely and the lockfile points at Lovable's private registry, so new npm deps are risky.
- All sharing goes through src/components/mm/ShareSheet.tsx (PeriPal message, WhatsApp, native/Web Share, copy, save picture) with picture cards from src/lib/share-cards.ts; picture cards (badges, garden, colouring, results, notes) share the image with the message and link attached (in the app via the Filesystem plugin, falling back to link-only on older app builds); articles share as /read/$id links that need a free account to read in full; why: one consistent, privacy-safe way to share that also works inside the Android WebView.
- Little notes (/notes) are scheduled on the phone with LocalNotifications (ids 7000-7199, topped up on app open, tap opens /notes?card=id); in browsers they use web push via a `little_notes` row in `reminders` sent by the 5-minute send-nudges job; nothing about the user picks the note; why: works signed out in the app and keeps the server out of it where possible.
- 37 tabs keeps typed tabs and the basket on this device (src/lib/tabs.ts) and mirrors Help me remember items in, syncing only after useRewards is ready; why: it's a brain dump, not account data, and syncing before load would wrongly drop remembered items.
- Garden tools (watering can, trowel) are dragged or tapped into place and tapped to use; watering is per plant for the visit and saves only the last-watered time; why: hands-on tending is the point, and it still never awards petals.
- Lumenera is the app: its welcome is /, its home /home, and spaces, checks and content live at /space/$id, /check/$id and /item/$id (src/lumenera); every other route is a tool page that AppShell wraps in the Lumenera phone frame with a shared top bar; /flowella and /every-season redirect to /; why: one app for every stage of life, with Pause in Play's tools as its menopause heartland.
- Lumenera styling: the shared --mm-* tokens and fonts in src/styles.css carry the Lumenera palette (Young Serif and Figtree), so Tailwind-styled tools restyle without per-screen edits; Lumenera's own classes live in src/lumenera/es.css under .es, with element defaults inside @layer base so tool utilities always win; why: one look across everything without rewriting each tool.
- The Lumenera profile (welcome answers) stays on the device in localStorage (es:profile) and drives tailoring in src/lumenera/engine.ts (tested); accounts, gardens, My people and admin use the existing Lovable Cloud tables unchanged; why: no health data is stored until Australian hosting and consent are in place.
- Medicines women search come from the admin-managed `medicines` table (approved only, tags, default_schedule jsonb, never doses) merged over the built-in list in src/content/medicines.ts, so the app works before migration 0016 is applied; names women add go anonymously to `medicine_suggestions` for the team to check in Admin → Medicines; why: one curated list the team controls, with a safe fallback.
- Medicine cabinet schedules (src/lib/cabinet.ts) are prefilled from the medicine's default schedule and edited by her; phone reminders use LocalNotifications ids 7300-7499, planned a week ahead on every change, with discreet titles by default; day maths rounds across daylight saving; why: reminders must fire on time without naming medicines on a lock screen unless she chooses.
- The Lumenera menu (top-right on home and tool pages) opens Guide (/guide, searchable explainers from src/lumenera/guide.ts), Quick tools (/tools), Lume Lounge, Lume Library (/library, all learn_content plus Lumenera items; /learn redirects) and Profile and account (/profile); why: one consistent place to find everything without crowding home.
- Home "Everyday tools" is a category rail (Recently used, Favourites, Practical help, Medicine cabinet, My body, Mood and mind, Fun therapy, Lume Lounge, Lume Library) defined in src/lumenera/tools.ts CATEGORIES; recent visits are noted by AppShell into lum:recent; hearts toggle favourites in useRewards; why: discoverable without a long grid.
- Your checks on home always shows a multiple of three (minimum three) via checksRow in src/lumenera/engine.ts, padding with skin, mind and life-stage prompts; why: no blank spaces in the grid.
